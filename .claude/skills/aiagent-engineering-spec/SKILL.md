# AI Agent 工程开发规范

本规范用于约束 AI Agent 类项目从设计到交付的全流程，目标是让 Agent 行为可复现、
可观测、可评测、可回滚。

## 一、项目结构规范

Agent 项目按职责分层，禁止把提示词、工具、业务逻辑混在单个文件里。

```
project/
├─ agent/
│  ├─ prompts/          # 系统提示词，一文件一角色
│  ├─ tools/            # 工具实现，一文件一工具
│  ├─ memory/           # 短期会话/长期记忆
│  ├─ planner/          # 任务分解与编排
│  └─ runtime.py        # 主循环
├─ configs/             # 模型、阈值、超参
├─ evals/               # 评测集与打分脚本
├─ logs/                # 运行轨迹
└─ README.md
```

## 二、上下文工程规范

1. 系统提示词必须版本化（文档版本号），改动须留 diff 记录。
2. 上下文按固定优先级装配：系统提示 > 工具定义 > 长期记忆 > 检索结果 > 历史对话 > 用户输入。
3. 每轮显式做 token 预算，超限时按上述优先级从低到高裁剪。
4. 禁止把未经验证的检索内容当事实写回长期记忆。

## 三、工具调用规范

每个 Tool 必须提供：

- 唯一 `name`，动词开头，如 `search_docs`
- 语义明确的 `description`：说明用途、何时用、何时不用
- 严格 JSON Schema 的参数定义，必填项显式标注
- 失败返回结构化错误码，禁止抛裸异常
- 幂等性声明：是否可安全重试

工具调用循环须设最大步数上限，超限即终止并返回已完成部分。

## 四、记忆系统规范

| 类型 | 存储 | 生命周期 | 写入条件 |
|---|---|---|---|
| 工作记忆 | 内存 | 单次会话 | 自动 |
| 短期记忆 | KV/Redis | 数小时 | 每轮摘要 |
| 长期记忆 | 向量库 | 持久 | 需通过事实校验 |

写入策略：去重 → 冲突检测 → 置信度打分 → 低于阈值丢弃。

## 五、评测规范

1. 评测集分为：冒烟集（<20 条，每次改动跑）、回归集（覆盖历史 bug）、能力集。
2. 每项任务定义可自动判定的成功条件，人工评分仅作兜底。
3. 评测必须可复现：固定随机种子、固定模型版本、固定工具 mock。
4. 记录每次评测的指标快照，用于对比回归。

## 六、可观测性规范

一次运行必须能回答：调了什么模型、用了哪些工具、消耗多少 token、耗时多少、在哪一步失败。

日志字段最小集：`run_id`、`step`、`model`、`tool`、`input_tokens`、`output_tokens`、`latency_ms`、`status`。

## 七、交付与验收

交付前逐项确认：

- [ ] 提示词与配置纳入版本控制
- [ ] 冒烟评测全绿
- [ ] 工具失败路径有测试覆盖
- [ ] 有超时、重试、熔断配置
- [ ] 有成本上限与告警
- [ ] README 写清运行方式与前置条件
- [ ] 保留可回滚的上一版本

## 八、常见问题

**Q：小项目也要这么重吗？**
A：结构和评测可裁剪，但提示词版本化、工具 Schema 严格化、日志最小集三条必须保留。

**Q：如何防止 Agent 幻觉写库？**
A：长期记忆写入前强制事实校验，校验不通过只能进短期记忆。

**Q：工具越加越多怎么办？**
A：按域分组，单次注入上下文只暴露当前任务相关工具子集，其余按需检索。
