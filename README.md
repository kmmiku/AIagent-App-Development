# AIagent工程开发规范 · Skill

一套面向 AI Agent 项目的工程开发规范，从架构设计到上线验收，让 Agent 行为可复现、可观测、可评测、可回滚。

**作者：GitHub@kmmiku**

**功能：** 为 AI Agent 类项目提供统一的工程约束——项目分层结构、上下文装配优先级、Tool Schema 规范、记忆系统写入策略、评测集分级、可观测性最小日志集、交付验收清单。适用于从零搭建 Agent 项目，也适用于给已有项目做规范化改造。

---

## 前提条件

- 支持 Skill 机制的 Agent 客户端（Claude Code、Codex 等），或任何能读取 Markdown 规范文档的开发流程。
- 项目中已有明确的 Agent 运行时（自研循环或框架均可）。
- 建议将本规范纳入版本控制，与业务代码同仓或独立仓库均可。

---

## 安装与使用

### 第一步：获取 skill

```bash
git clone https://github.com/kmmiku/AIagent-Engineering-Spec.git
```

### 第二步：安装到客户端 skills 目录

将 `aiagent-engineering-spec` 整个目录放入你所用客户端的 skills 路径：

- Claude Code：`~/.claude/skills/aiagent-engineering-spec/`
- Codex：`~/.codex/skills/aiagent-engineering-spec/`

目录内必须包含 `SKILL.md`，其 YAML frontmatter 提供 `name` 与 `description`，客户端据此决定何时加载。

### 第三步：在会话中触发

在开发 Agent 项目时直接提问，例如：

- 「帮我为这个 Agent 项目建立目录结构」
- 「设计这套工具调用的 JSON Schema」
- 「给这个 Agent 搭一套评测集」
- 「上线前按规范帮我做一次验收检查」

客户端匹配到 `description` 后会自动加载本 skill 并按其条款给出方案。

### 第四步：按清单落地

skill 正文包含八个部分：项目结构、上下文工程、工具调用、记忆系统、评测、可观测性、交付验收、常见问题。建议按「结构 → 上下文 → 工具 → 记忆 → 评测 → 验收」顺序推进。

## 规范要点速览

| 部分 | 核心约束 |
|---|---|
| 项目结构 | 提示词、工具、记忆、编排分目录，禁止混在单文件 |
| 上下文工程 | 固定优先级装配，每轮做 token 预算并按优先级裁剪 |
| 工具调用 | 名称动词开头、描述含「何时不用」、严格 JSON Schema、结构化错误 |
| 记忆系统 | 工作/短期/长期三级，长期写入须过事实校验 |
| 评测 | 冒烟集、回归集、能力集分级，固定种子与模型版本 |
| 可观测性 | 每条运行记录 run_id、step、token、latency、status |
| 交付验收 | 七项 checklist，缺一不可 |

## 自定义与优化

- **裁剪结构**：小项目可简化目录层级，但提示词版本化、工具 Schema 严格化、日志最小集三条必须保留。
- **调整评测门槛**：在 `evals/` 中按项目风险等级增删回归集条目，高风险模块要求覆盖率更高。
- **扩展日志字段**：最小集之外可按需增加业务字段，但不要删除 `run_id` 与 `step`，否则轨迹无法串联。

## 常见问题

**Q：小项目也要这么重吗？**
A：结构和评测可裁剪，但提示词版本化、工具 Schema 严格化、日志最小集三条必须保留。

**Q：如何防止 Agent 幻觉写库？**
A：长期记忆写入前强制事实校验，校验不通过只能进短期记忆。

**Q：工具越加越多怎么办？**
A：按域分组，单次注入上下文只暴露当前任务相关工具子集，其余按需检索。

**Q：规范文档改了会影响老项目吗？**
A：规范纳入版本控制，老项目锁定其引入时的版本 tag，避免规范升级直接冲击线上。

**Q：这套规范和具体框架绑定吗？**
A：不绑定。规范只约束职责划分与验收标准，LangChain、自研循环或其他框架都可套用。
